# 风格基因拆解（Style DNA）

从 5 张「鸿蒙手绘课堂」知识卡片（assets/ 下 ref-01 ~ ref-05）萃取出的风格规范。生成任何新卡片时，本文件的每一条都必须体现在提示词中。

## 1. 画风媒介

- **手绘涂鸦风**：如同用蜡笔、彩铅、马克笔在速写本上亲手绘制。
- 线条带有自然抖动、断续、不完美感，禁止尺规般的直边。
- 色块有手涂质感（轻微的不均匀、超出边界一点点）。
- 边框一律为手绘圆角矩形，可轻微歪斜。
- 整体气质：温暖、治愈、零距离，像优秀老师的手写板书。
- **禁止**：写实照片风、3D 渲染风、商务扁平风（Material/Linear 图标风）、暗黑背景、赛博朋克、油画画笔触。

## 2. 五层统一骨架（每张卡必备，缺一不可）

| 层 | 位置 | 内容 | 规范 |
|---|---|---|---|
| L1 标题区 | 顶部通栏 | 口语化**疑问句**大标题 + 副标题 + 角落便利贴 | 见 §3、§6 |
| L2 中央图示区 | 画面中部 | 一个核心视觉隐喻场景 + 2–4 个信息块 | 见 §4、§5 |
| L3 连接层 | 贯穿 | 粗箭头/弧形箭头（带文字标签）+ 角色对话气泡 | 见 §6 |
| L4 结论条 | 底部通栏 | 浅黄横幅 + 灯泡图标 + **一句话核心结论** | 见 §6 |
| L5 页脚 | 最底部 | 仅一行小字：依据 + 官方来源 | 见 §8 |

## 3. 标题句法（L1）

- 主标题必须是**口语化疑问句**，制造好奇心缺口。5 张实证：
  - 「MQTT 消息怎么找到你？」
  - 「耗时计算交给谁？」
  - 「鸿蒙数据存储怎么选？」
  - 「ArkUI 状态怎样传？」
- 主标题放在手绘丝带/横幅里（可轻微倾斜、胶带粘贴感），粗体大字，带轻微描边，主题色。
- 副标题给知识点坐标，格式「XX · YY」，如「ArkTS 并发选型 · TaskPool 与 Worker」。
- 左上或右上贴 1–2 张黄色便利贴，写补充规则/边界提示（如「本图是通用协议原理；平台接入需遵循 Topic 与权限规则」）。

## 4. 中央视觉隐喻（L2 核心）

每张卡必须有一个**生活化大场景**作为知识点的心脏，知识点元素拟人化嵌入场景。5 张实证：

| 卡片 | 知识点 | 视觉隐喻 |
|---|---|---|
| ref-05 MQTT | 发布/订阅 | 邮局：Broker = 邮局店员，Topic = 信封地址 |
| ref-04 并发 | TaskPool/Worker | 工坊流水线：机器人 worker 在传送带上搬箱子 |
| ref-03 存储 | Preferences/KV/RDB | 书架图书馆：猫管理员 + 放大镜 + 三列书架 |
| ref-02 状态管理 | @Param/@Event | 计数器回路：父/子组件间上下两条弧形箭头闭环 |
| ref-01 生命周期 | 四个回调 | 旅程：铁轨 + 4 个站点 + 昼夜背景 + 行李箱 |

设计新隐喻的方向：邮局/快递、厨房、交通、图书馆、工厂、旅行、游戏——选学员一看就懂的生活场景。

## 5. 信息块规范（L2 构件）

- 白底、圆角、主题色手绘描边（2–3px 感）。
- 块内顶部：彩色粗体小标题（如「订阅者 Subscribe」）。
- 块内正文：圆点或短横列表，短句，暖深色文字。
- 代码/API 名用**等宽字体标签**样式呈现（如 `@Local count`、`key: user1`、`room/temp`）。
- 字号对比强烈：块标题大、列表小。
- 流程类卡片加**编号步骤** ①②③ 说明过程。

## 6. 角色与细节元素库（L3）

**角色系统（IP 感，跨卡保持一致）：**
- **蓝色小机器人吉祥物**：每张必出现，圆滚滚、白脸、弧线笑眼，随场景换装（邮差/工人/背包客）。
- **Q 版小女孩**：每张必出现，按知识点换职业装（邮局员/工程师/研究员/开发者/旅行者），粗描边、高腮红。
- **拟人化设备**：笔记本电脑、手机画上笑脸。
- **动物点缀**：偶尔加猫等动物（如 ref-03 的猫管理员）。
- 角色会说话：头顶对话气泡，第一人称口语台词（如「我负责显示，你来点我！」「我按 Topic 匹配并转发」）。

**细节元素库（按需取用）：**
对话气泡、粗箭头、弯曲箭头、灯泡、问号、星星闪光、胶带、图钉、黄色便利贴、书本堆叠、植物、放大镜、工具箱、流程编号 ①②③。

## 7. 色彩纪律

- **一卡一主色**：全卡约 70% 视觉权重集中在单一主题色上。
- 背景 = 该主题色的极淡 tint（明度 92%+）。
- 信息块统一白底，文字用暖深色（#4A3F35 一类的深棕）。
- 允许的全局点缀色：浅黄便签、木棕色、白色、角色固有色（蓝机器人、棕发女孩）。
- **除主题色 + 点缀色外不得出现杂色**。
- 具体色值见 `color-system.md`。

## 8. 结论条与页脚（L4/L5）

- 结论条：底部通栏浅黄横幅，左侧灯泡（或旗帜）图标，中间写**一句话核心结论**，常为「A → B → C」式流程句，如「发布者 → Broker → 匹配主题的订阅者」「主线程发起任务 → 子线程处理 → 主线程更新 UI」。
- 页脚仅一行小字：「依据：{官方来源}」（如「依据：华为 XX 官方文档」）。
- **页脚只写依据，其他什么都不要写**：不写课程名、课程序号、课纲主题等任何其他信息。

## 9. 负面清单（生成后逐条自检）

- ❌ 写实照片 / 3D 渲染 / 商务扁平 / 暗黑背景
- ❌ 一卡出现多个主色（杂色）
- ❌ 纯文字排版、无角色、无场景
- ❌ 标题不是疑问句
- ❌ 缺结论条或缺依据页脚
- ❌ 中文错别字超过 2 处（需重新生成）
- ❌ 画面拥挤、无留白
