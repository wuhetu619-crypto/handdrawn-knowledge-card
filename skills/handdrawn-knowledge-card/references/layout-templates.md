# 五种版式原型（Layout Templates）

由 5 张参考卡归纳出的 5 种构图原型。新卡片先判型，再选原型。

## 判型速查

| 知识点类型 | 选用原型 | 实证卡片 |
|---|---|---|
| 流程 / 机制 / 协议（谁发给谁、怎么流转） | **A 流程分发型** | ref-05 MQTT |
| 对比 / 选型 / 决策（A 还是 B、怎么选） | **B 对比选型型** | ref-04 并发（双栏）、ref-03 存储（三栏） |
| 双向交互 / 状态流转（数据怎么去、事件怎么回） | **C 双向回路型** | ref-02 状态管理 |
| 阶段 / 周期 / 生命周期（有几个阶段、顺序如何） | **D 旅程路线型** | ref-01 生命周期 |
| 概念科普 / 系统全景（拟人化讲一个大场景） | **E 中央隐喻大场景型** | （备用，参考 ref-05 的邮局场景放大） |

## A 流程分发型

**构图**：左中右三段式。左侧「生产者/发起方」角色 → 中央枢纽大场景（占画面中心且最大）→ 右侧「消费者/接收方」。
**必需元素**：弧形箭头从左→中、中→右，各带文字标签；如有回传，加回程箭头；中央枢纽内的拟人角色配台词气泡。
**结论条句式**：「生产者 → 枢纽 → 匹配条件的消费者」。
**变体**：单向流程省略回程箭头；多级流程用折线串联 2–3 个枢纽。

## B 对比选型型

**构图**：顶部居中一句引导问题（如「你要保存什么？」），下方 2–3 个**等宽并列**白色信息块。
**每块结构**：小图示 + 标题 + 适用场景 + 圆点要点列表 + 一句实例。
**选型卡加分项**：问题与信息块之间画「分流」视觉（漏斗/三岔箭头），强调「一个问题分流到 N 个方案」。
**结论条句式**：给出选型口诀，如「少量设置 → 首选项；简单数据 → KV 库；复杂查询 → 关系型数据库」。
**注意**：块数 2–3 个为宜，超过 3 个改用 D 型或拆卡。

## C 双向回路型

**构图**：画面中央放置核心对象大图示；上下各一条粗弧形箭头形成闭环——向下箭头标注「数据流」（如 `数据向下：@Param`），向上箭头标注「事件流」（如 `事件向上：@Event`）；左右两侧各放一个角色/组件框对峙。
**必需元素**：闭环箭头 + 两侧角色台词气泡 + 底部 ①②③ 编号步骤条说明闭环过程。
**结论条句式**：「父组件持有状态，子组件用事件表达修改意图」式的一句话机制总结。

## D 旅程路线型

**构图**：画面中部一条横向手绘轨道/小路从左到右贯穿，依次经过 N 个站点（2–6 个）；每站 = 圆形序号 + 阶段名图标 + 回调名/职责一句话。
**必需元素**：站点图标随阶段变色/变形；如存在回环（如前后台切换），在轨道下方画回程弧形箭头并标注；背景可表现时间流逝（昼→夜）呼应阶段语义。
**结论条句式**：「XX 回调要轻量，耗时工作移交子线程」式的最佳实践提醒。

## E 中央隐喻大场景型

**构图**：一个占画面 60% 以上的大型生活化场景占据中心，知识点元素全部拟人化嵌入场景；2–4 个小信息块像便签一样贴在场景四周；台词气泡从场景角色口中说出。
**适用**：概念科普、系统全景、协议原理类。
**注意**：信息块只放关键词，细节交给场景演绎；避免场景与信息块争夺视觉中心——信息块保持小而精。

## 通用构图纪律

- 视觉动线：标题（上）→ 中央图示（中）→ 结论条（下），从左到右阅读。
- 留白：画面至少 15% 为呼吸区，信息块之间不贴边。
- 每个原型的中央区域必须出现至少 1 个角色（小女孩或机器人），不得是纯图形。
- 箭头一律粗壮、带圆头，标签文字压在箭头上或紧贴箭头。
